**Headline: SBG is not validated as a behavioural-change detector.** The v8 test result (SBG V5 0.694 vs reversed edit size 0.876,
verdict NOT DEMONSTRATED) stands. A new frozen evaluation on a size-decoupled design shows SBG carries information beyond a single
pair's edit size, but not beyond edit size plus simple execution statistics, and it loses to edit size inside matched sets.
No evidence of transfer to real bugs.

## 1. Root cause of the edit-size shortcut (`LABEL_GENERATION_AUDIT.json`, uses no SBG scores)
* Code: `benchmark/scripts/generate_v8_dataset.py::generate_split` binds label to family at the call site
  (`("EQUIVALENT", SP_TYPES, apply_transformation)`, `("CHANGED", SC_TYPES, apply_mutation)`); `semantic_relation == expected_label`; every family has exactly one label.
* Data: all SC families have median edit 2 lines (SC-13: 3); SP families range 4–16 (SP-2 median 2 is the overlap family). Train edit-size bucket vs label: edit=2 → 81 % CHANGED; 6–10 → 1.9 %; 11–20 → 1.7 %; 21+ → 0 %.
* Independent reversed-edit-size AUROC (canonical lines): train 0.849, dev 0.877, val 0.885, test 0.876; raw-line and token measures 0.73–0.76 on train. Forward + reversed = 1; ties by midrank; orientation correct.
* Verdict: a **dataset-design confound** (label determined by transformation family, and families differ in size). Not an implementation, orientation or leakage error. Exact-size stratification keeps only 17–23 % of cross-label pairs, so it changes the population.

## 2. Does SBG add value beyond edit size? (`V9_VAL_EVALUATION.json`, CONFIRMATORY-BY-FREEZE)
Design v9_composed: each v8 EQUIVALENT pair is kept verbatim; its CHANGED partner is `SP_t,s(SC_k(p))` (same rewrite, same seed, plus a mutation), scored against the original program. Plan `docs/current/EVALUATION_PLAN_V9.md` and `FREEZE_V9.json` were committed (6dd5a0f) before any val score was opened; val run once.

Val: 11 never-scored programs, 432 matched-complete pairs (216 sets). Cluster bootstrap by program, 2000 resamples; Holm over H1–H4.

Caveats that must accompany any positive wording:
* Edit size is **not eliminated** in v9 (forward edit AUROC 0.61 pooled; paired difference +2 lines in ~76 % of sets).
* Matched-set concordance: edit size ranks the CHANGED partner higher in 92.4 % [90.7, 94.3] of sets vs SBG 80.6 % [73.8, 86.1]. Inside a matched set the edit-size shortcut beats SBG.
* 37 % of sbg_v5 scores are exactly 0. Exact-edit-size-stratified sbg_v5 = 0.735 (3801 comparisons).
* sbg_state ≈ sbg_v5 (Δ −0.011 [−0.040, 0.024]); state-only was picked on dev, exploratory.
* All programs are synthetic, 11 val programs, one dataset family. The v8-design val replication shows the confound again (sbg_v5 0.685 vs reversed edit 0.885).
* Dev (exploratory) and train (in-sample) show the same pattern; train H4 is significant (+0.039) but is in-sample.

## 4. Real-bug results (`EXTERNAL_RESCORE_V8.json`, `EXTERNAL_NEGATIVE_AUDIT.json`; EXPLORATORY)
Labels, pairing, orientation verified earlier (`DIAGNOSTIC_EXTERNAL.json`). Rescore with purge-per-extraction and structural entry policy, same pairs:

| Corpus / subset | n pairs (pos/neg) | AUROC | 95 % CI (cluster) |
|---|---|---|---|
| BugsInPy original v7 (reference) | 147 (41/106) | 0.410 | [0.326, 0.494] |
| BugsInPy rescored, all | 147 (41/106) | 0.416 | [0.322, 0.514] |
| BugsInPy rescored, excl. SP-2 | 107 (41/66) | 0.497 | [0.402, 0.596] |
| QuixBugs canonical, original v7 | 152 (40/112) | 0.388 | [0.285, 0.503] |
| QuixBugs canonical, rescored, all | 151 (39/112) | 0.384 | [0.285, 0.490] |
| QuixBugs canonical, rescored, excl. SP-2 | 111 (39/72) | 0.444 | [0.355, 0.539] |

* The corrected harness does **not** lift either corpus above chance, so the harness defects are not the explanation for the sub-0.5 point estimates. Excluding SP-2 moves BugsInPy to ≈0.5 (CI covers 0.5).
* Mechanisms supported by data: 26/41 BugsInPy and 32/39 QuixBugs real-bug pairs have sbg_v5 exactly 0 (canonical synthesised inputs do not expose the fix). In BugsInPy, the 10 SP-2 negatives scoring > 0.1 are exactly: 7 provably invalid variants (nested `fix_kv` renamed to `fn_fix_kv`, call site unchanged → `NameError`; scores 0.79–0.80; `EXTERNAL_NEGATIVE_AUDIT.json`) plus 3 units (`black/21`, `black/23`, `youtube-dl/37`) whose base has non-zero self-distance (0.60–0.67; first-extraction-in-process effect, `raw/cold_start_probe.json`). Removing the 7 invalid negatives moves BugsInPy to 0.445 (point estimate, n=140); removing them and all SP-2 gives 0.497.
* No root cause is claimed for the residual sub-chance values; the CIs include 0.5 once SP-2 is excluded. **Do not claim real-bug generalisation, and do not claim a below-chance effect is "explained".**

* **No independent v9 test**: a v9 test split was deliberately not generated (the only remaining unseen programs are the burned v8 test programs; reusing them would not be independent of the v8 test examination). A genuinely new confirmation needs new unseen base programs. Blocker: base-program authorship, not compute.
* Real-bug benchmark with validated negatives and declared inputs for all units; Java QuixBugs; warm-up-normalised external harness (requires an extraction-semantics change → new freeze).
* Stanford gate: 8/20 PASS, 12 BLOCKED (novelty, generalisation, publication readiness).

## 7. Safe claims for the paper
1. Label-bound-to-family design makes edit size alone a 0.85–0.89 AUROC shortcut on v8 (all four splits, independent code, three size measures); SBG V5 is below it on v8 test (0.694 vs 0.876, Δ −0.182 [−0.220, −0.144]).
2. On a size-decoupled composed design, with a frozen single evaluation on 11 unseen synthetic programs, SBG V5 achieves AUROC 0.751 [0.706, 0.794] and adds information beyond edit size (Δ +0.112 [0.075, 0.148]) and beats coverage, exception and call-count baselines.
3. SBG does **not** significantly add beyond edit size + simple execution statistics (Δ +0.021 [−0.005, 0.048]), and within matched sets edit size alone ranks 92 % vs SBG 81 %.
4. Real-bug transfer is not shown (BugsInPy/QuixBugs ≈ chance or below; exploratory, flawed negatives documented).
Unsupported: "SBG is validated", "SBG generalises to real bugs", "SBG beats edit size" (except on the unmatched pooled v9 AUROC, which is a population artefact), "state component is best" (post hoc).
