## 1. Executive verdict

**READY AFTER SPECIFIED REMEDIATION.** This is a verdict about the evidence package and about permission to start drafting. It is not a prediction about acceptance.

The empirical package supports one defensible positive claim and several clearly bounded negative ones.

- **Positive, bounded.** On 19 held-out programs generated by the project's own pipeline (V10), V5 separates behaviour-changing from behaviour-preserving variants with pooled AUROC 0.8968. It beats forward edit size (0.616) and the edit-size-controlled comparison (0.875 vs 0.5). The advantage is uniform across programs (19/19) and stable to leave-one-out. This is same-author, same-generator evidence.
- **Not established.** Incremental value beyond execution statistics (H4); independent external validity; real-bug detection (BugsInPy 0.410, QuixBugs 0.388); component necessity; any cross-language claim; version stability of the frozen results beyond CPython 3.12+.
- **Preserved negative evidence.** V8 (V5 0.694 vs reversed edit-size baseline 0.876) shows edit-size confounding can reverse conclusions.

Remediation required before drafting is writing and framing work, not new experiments. See §14 and §15.

## 2. Frozen V10 results and interpretation — VERIFIED

Sources: `artifacts/paper_evidence/V10_INDEPENDENT_EVALUATION.json`, `artifacts/final/pairs_v10_test_v6exp.jsonl`, `artifacts/final/V10_MODELS_FROZEN.json`. Recomputed by independent code in `agent_1/verify_program_robustness.py` and `agent_4/scripts/audit_v10_independent.py`.

| Quantity | Value |
|---|---|
| Programs / pairs / matched sets | 19 / 638 / 319 (3 non-terminating pairs and their partners dropped by the frozen matched-complete rule) |
| V5 AUROC (95% cluster CI) | **0.896768** [0.8629, 0.9216] |
| Forward edit size | 0.616046 |
| M_EX (execution statistics) | 0.790789 |
| M_EX + V5 | 0.797088 |
| H1 V5 > 0.5 | adj. p = 0.003, rejected |
| H2 E+V5 − E | adj. p = 0.005, rejected |
| H3 V5 − edit | adj. p = 0.005, rejected |
| **H4** EX+V5 − EX | **+0.0063, CI [−0.069, 0.068], adj. p = 1.0 — not established** |
| H5 / H6 (V6 variants) | adj. p 0.090 / 1.0, not rejected |
| Edit-size-controlled AUROC (n = 8,605 comparisons) | V5 0.875; edit 0.5 |
| Exact-zero rate | 34.6% of all pairs: 63.6% of EQUIVALENT, 5.6% of CHANGED |

Holm family is **six** hypotheses (H1–H6).

**Interpretation.**
1. V10 is a held-out-program evaluation. Programs, generators and labelling rules come from the same authors, so it is not independent external validation.
2. The unit of inference is 19 program clusters, not 638 pairs. A naive pair bootstrap gives a slightly narrower interval ([0.870, 0.919]) than the cluster bootstrap and should not be used.
3. On the matched-set metric (each CHANGED variant vs its own partner), **forward edit size scores higher than V5** (0.9545 vs 0.931), because CHANGED variants almost always carry the larger edit (mean +1.93). Anything said about V5 "beating edit size" must name the metric.
4. V5 is sparse. About two thirds of EQUIVALENT pairs score exactly 0, and 73.9% of value-only (SC-6) changes score exactly 0 (AUROC 0.451).

## 3. Per-program robustness — VERIFIED (exploratory)

Source: [`../agent_1/agent_1_program_robustness_final.md`](../agent_1/agent_1_program_robustness_final.md). 79 numeric checks against the previous sprint, 0 mismatches, plus Agent 4's separate recomputation.

- Per-program V5 AUROC: 0.705–0.970, mean 0.893. Three programs are below 0.80 (`graph_topological_kahn`, `sort_radix_sort_lsd`, `str_group_anagrams`).
- V5 vs edit: **19/0/0**, mean +0.259, sign-test p = 3.8e−6.
- V5 vs M_EX: **14/5**, mean +0.095, p = 0.064. Not significant; the median (+0.039) is far below the mean.
- Leave-one-program-out V5: 0.8922–0.9062. V5−edit stays within +0.275 to +0.289. V5−M_EX stays positive in all 19 subsets. This shows no single program drives the result; it is not a generalisation test.
- **Within vs between programs.** Within-program concordance 0.891 (5,567 comparisons, 5.5%); between-program 0.897 (96,194, 94.5%). The pooled AUROC is dominated by cross-program comparisons, which are correlated through shared programs and transformation families. The effective sample is about 19 programs.
- **Limits.** Nineteen same-author programs in five categories (ds 3, graph 4, math 3, sort 7, str 2); no category-level inference; per-program intervals are wide (7–24 pairs per class); sub-analyses are not multiplicity-corrected.

## 4. Component ablation — VERIFIED values; findings PRELIMINARY (post-hoc)

Sources: `paper/empirical_sprint_2026-11-04/agent_1/agent_1_component_ablation.md` and CSVs. V10 AUROCs reproduced in Agent 4's tables.

| Variant | V10 AUROC |
|---|---:|

| Without V3 | 0.9053 |
| Without temporal | 0.9036 |
| Without state | 0.8821 |
| V3 only | 0.8817 |

- The weights provenance check passes: `0.50·V3 + 0.25·temporal + 0.25·state` reproduces stored V5 to 7.5e−10.

- **Do not** present state-only as the primary method, re-weight V5 after seeing V10, or claim every component is necessary. The honest reading is that V5's composite weights are not shown to be optimal and the temporal and V3 contributions are not demonstrated on this evidence.

## 5. Real-bug failure taxonomy — mixed; primary results VERIFIED, mechanism PARTLY NOT ESTABLISHED

Sources: `artifacts/final/pairs_{bugsinpy,quixbugs_canonical}_output_free_v7.jsonl`, `artifacts/paper_evidence/{EXTERNAL_RESCORE_V8,EXTERNAL_NEGATIVE_AUDIT,DIAGNOSTIC_EXTERNAL}.json`, `raw/bugsinpy_purge_rescore.json`; report [`../agent_2/agent_2_real_bug_failure_taxonomy.md`](../agent_2/agent_2_real_bug_failure_taxonomy.md) (carries an audit notice); audit §3.

**VERIFIED (primary, frozen; report prominently).**

| Corpus | Pairs (pos/neg) | Clusters | V5 AUROC | 95% cluster CI |
|---|---|---:|---:|---|
| BugsInPy v7 | 147 (41/106) | 39 | **0.4099** | [0.3262, 0.4939] |
| QuixBugs canonical v7 | 152 (40/112) | 40 | **0.3877** | [0.2847, 0.5034] |

- 53 BugsInPy pairs (14 positives, 39 negatives) were not evaluable (49 unsupported signature, 4 import error) and are excluded from the headline. This is a selection effect that should be disclosed.
- Exact zeros among the 41 BugsInPy positives: **21** (committed v7) → **24** (after `re.purge()`; `youtube-dl/6`, `/7`, `/26` had regex-cache-contaminated scores of 0.61–0.68) → **26** (v8 rescore; `luigi/14` and `youtube-dl/31` also flip). V5 temporal = 0 on 26 pairs in v7 is a different quantity that coincidentally equals 26, which explains the 21-vs-26 confusion.
- QuixBugs: 32 of 40 positives score exactly 0.
- Seven EQUIVALENT BugsInPy negatives have invalid labels (nested helper renamed without updating call sites; V5 0.71–0.80).
- SC-6 (value-only) changes are invisible by design: 17 of 23 synthetic examples score 0.

**PRELIMINARY / exploratory, never primary.** Excluding all SP-2 negatives gives 0.497 (BugsInPy, v8 scorer, CI [0.402, 0.596]) and 0.444 (QuixBugs, v8 scorer, CI [0.355, 0.539]); on the committed v7 scorer the values are 0.4715 and 0.4507. These intervals include 0.5. They are inconclusive and not evidence that SBG performs at chance. QuixBugs declared-input AUROC 0.7022 is a survivor subset (99 of 152 pairs) and must not be promoted.

**NOT ESTABLISHED (withdrawn from Agent 2's report).**
- The seven-category counts, in particular "genuine representation failure" (many of these pairs are correctly scored 0).
- "Fault not reached" as a causal label (no coverage artifact; the QuixBugs crash sets are hard-coded with no source).
- "100% of SP-2 negatives are scored as changes" (actual: 37/40 v7, 36/40 v8 in BugsInPy; 31/40 and 29/40 in QuixBugs, with a mean of only 0.014).
- Self-distance values and their stated cause; and `luigi/14` as an entry mismatch.

**What can be said.** Transfer is negative (below chance, interval upper bound 0.49 for BugsInPy). Contributing factors supported by artifacts: many positives show no difference on the supplied inputs, output-free design hides return-value changes, and known harness defects inflate negatives. The *relative size* of these factors is unknown.

## 6. Python environment sensitivity — VERIFIED stored numbers; scope PRELIMINARY

Source: `artifacts/final/PYTHON_VERSION_SENSITIVITY.json`; `paper/empirical_sprint_2026-11-04/agent_4/agent_4_environment_sensitivity.md`.

- Stored artifact compares CPython 3.9.6 vs 3.13.x on **39 toy rows** (15 regression pairs, 12 hard-negative pairs under two input regimes). 34 of 195 distance fields change; the largest change in any field is 0.4085 (a `state` field on REG_09), not a change in headline V5.
- Spearman agreement of V5 across 3.9.6 vs 3.13.5: 0.968 (REVIEWED; not recomputed here). No decision flips at the τ = 0.08 operating point.
- Dominant mechanism: PEP 709 comprehension inlining in CPython 3.12 removes a `<listcomp>` frame. 3.12, 3.13 and 3.14 are bit-identical on this suite; 3.9 and 3.11 differ.
- **No V6–V10 pair was in the study.** It does not show V10 is version-stable. Frozen results should be stated as valid for CPython 3.13 (≥ 3.12 expected).
- **Unresolved:** artifact and lockfile say CPython 3.13.15; `FREEZE_V8/V10` say 3.13.5. Output was bit-identical on 3.13.5, but the actual producing interpreter is unattested.

## 11. Confirmed limitations

1. **Nineteen independent clusters** in the headline (11 in V9c).
2. **Same-author, same-generator** programs, transformations and labels (V8–V10). Not external.
3. **Labels are protocol-input equivalence**, not formal semantic equivalence.
4. **H4 not established**; M_EX is a strong baseline (0.79) and the V5-over-M_EX advantage is not uniform (14/5).
5. **Edit-size confound** is real (V8 reversal) and V5 does not beat edit size on matched-set concordance.
6. **Output-free design is blind to value-only changes** (SC-6).
7. **Real-bug transfer is negative**: BugsInPy 0.410, QuixBugs 0.388; 21/41 and 32/40 real-bug positives score exactly 0; a large share of real pairs was unevaluable.
8. **Ablations are post-hoc**; state-only is the best single component on V10.
9. **Version sensitivity** is bounded by a 39-row toy study; CPython 3.12+ only.
10. **No cross-language evidence.**
11. **Sparsity.** Many exact zeros reduce ranking resolution; tie handling matters.

## 12. Claims supported by evidence

- V5 achieves AUROC 0.897 on 19 held-out programs of the project's own benchmark; above chance and above forward edit size after Holm correction (H1–H3), with a uniform per-program advantage over edit size.
- V5's advantage over edit size persists when edit size is controlled (0.875 vs 0.5).
- Results are stable to leave-one-/two-program-out.
- On V9c (11 programs) V5 reaches 0.751; on V8 it did not beat the reversed edit-size baseline, and this is reported.
- Transfer to BugsInPy and QuixBugs under the output-free protocol is below chance, with documented harness artifacts.
- Value-only behavioural changes are not detected by design.
- A JVM trace bridge exists and runs; GnuCOBOL tracing is technically possible.

## 13. Claims that must not be made

- That V5 is externally validated, independent, or generalises across programs or domains.
- That V5 adds value beyond execution statistics (H4).
- That V5 detects or predicts real-world bugs.
- That the failure taxonomy proves *why* real-bug transfer fails, or that "fault not reached" explains it.
- That SBG performs at chance on real bugs once harnesses are cleaned (the intervals are inconclusive).
- That state-only (or any ablated variant) is the proposed method, or that all components are necessary.
- That results are stable across Python versions, or that V10 was checked across interpreters.
- Any SeqCoBench, Java or COBOL performance statement.
- That "equivalent" means formally semantically equivalent.
- That "edit size is beaten" without naming the metric.
- That 638 pairs or 101,761 comparisons are independent samples.

## 16. Final recommendation

**Decision gate.**

1. *Is SBG empirically strong enough to begin manuscript preparation?* Yes for a paper whose claim is bounded: a behavioural-representation method with a verified held-out-program result and honestly reported negative evidence. No for a paper claiming external validity, real-bug detection or generality.
2. *Is a new external benchmark evaluation essential first?* No, provided it is stated as a limitation and the SeqCoBench protocol as future work. It would materially strengthen the paper but was not a prerequisite to drafting.
3. *Is Java evaluation necessary first?* No.
4. *Should COBOL be deferred?* Yes.
5. *Minimum remaining work before drafting:*
   - (a) Fix the claim language in §12–13 and adopt the audited real-bug statements only.
   - (b) Report H4 as not established and V8 as a negative.
   - (c) Name the metric whenever comparing with edit size; include the matched-set concordance caveat.
   - (d) Record interpreter provenance (3.13.5 vs 3.13.15) and the CPython-3.13 scope.
   - (e) Decide the fate of `STANFORD_GATE.json` and add the Java claim-removal record.
   - (f) Optionally, rebuild the reach analysis with coverage data if a mechanism claim for real-bug failure is wanted. Otherwise do not make one.

**Verdict: READY AFTER SPECIFIED REMEDIATION.** Completion of this sprint does not imply the paper is ready for submission.
