# V7-B core: implementation status

Authority: `reports/final/V7B_FROZEN_SPEC.md`. All thresholds are the UNVALIDATED defaults. Nothing here claims equivalence of any pair.
Run: `python -m sbgv7 compare BASE.py VARIANT.py --entry F --inputs inputs.json --config cfg.json --out DIR`
(exit 0 verdict written, 2 invalid config/inputs/usage, 3 `ineligible:identical`). Verify: `python -m sbgv7 verify DIR` (0 recomputed verdict equals recorded, 1 mismatch/inconsistency detected, 2 unreadable/missing, 4 evidence omitted by size cap). Tests: `.venv/bin/python -m pytest tests/v7`.

## Modules (sbgv7/)
`records.py` types + content-addressed ids + hash-chained JSONL log + `trace`; `compare.py` boundary comparator; `config.py` strict
validation; `harness.py` child-side executor (monitoring-based line/branch capture); `runner.py` glue, replay protocol, activation;
`decide.py` pure verdict/sufficiency; `__main__.py` CLI. V5/V6 untouched; `sbgv6.features.changed_lines` is imported read-only.

## Implemented
- Verdicts DIVERGENT_OBSERVABLE > INSUFFICIENT(primary; secondary by rank B1..B9) > NO_DIVERGENCE_OBSERVED(S1|S2). `Verdict` asserts a closed
  value/reason-code enum; no equivalence value exists. S0 only appears inside INSUFFICIENT's SufficiencyRecord. Missing records are blockers (`tool_error`).
- Per-input outcomes: CONFIRMED_DIFF, UNCONFIRMED_DIFF (sub-labelled intermittent / failed_reproduction), ENV_SENSITIVE_DIFF, SAME,
  QUARANTINED (nondeterministic), LIMIT_ASYMMETRIC, NO_RUN (both sides limit).
- Protocol: r_det repeats (early stop on first disagreement), r_replay fresh replays per side, k_alt alternate control runs (seeded RNG + shifted clock).
- Comparator: return, exception (exact qualified type, normalised message or `ignore`), stdout, sandbox-temp files, argument post-call state,
  module globals written, API break (argument-binding failure). Type tag is identity, binary64-exact floats (NaN equal, -0.0 != 0.0), optional tolerance, mapping/set order-insensitive, objects to depth 3, `lossy` flag blocks S2.
- Terminals: returned/raised/exited/crashed(signal)/bind_error; timeouts and resource kills are limits, never witnesses.
- Changed-region activation: `changed_lines` intersected with executable lines per side; a unit is hit only by deterministic-confirmed SAME inputs.
- S1/S2 floors as in the spec section 6; S2 branch coverage = observed branch directions / 2 x branch instructions on changed lines, per version.
- Evidence log `DIR/evidence.jsonl` (chain verified by `records.read_log`), `DIR/verdict.json`; `records.trace(log, verdict_id)` walks verdict -> Witness/SufficiencyRecord -> runs -> observations/versions. Run/Witness ids are content-addressed and stable across invocations.
- Stored per run: slot-based id, status, observation id, hit lines (not a hashed event stream).

## Not implemented (honest gaps)
- S3 (refused in config, never emitted), explorer, module E / `internal_divergence`, input generation (inputs are user-supplied JSON values only: no tuples/sets/objects).
- Spec codes never produced: `ambiguous_entry`, `unmodelled_change`, `unsafe_program` is produced only for a result-protocol violation or the monitoring-state tamper flag (both now wired into `Evidence.tampered` and a per-input blocker; see V7B_RESULT_PROTOCOL.md), `blind_spot_dominant`, `alignment_failed` (only on parse failure). Entry-lifting to an outer frame and declared renames are not done; entry must be a top-level function.
- Isolation is the existing `sbgv7.isolation`: macOS `sandbox-exec` only, no Linux container path; every macOS record carries `policy_below_minimum=true` (spec: synthetic/benchmark only). Interpreter/tracer build mismatch handling (replay `inconclusive`) is absent. Dependency/runtime byte-identity check covers the source file only.
- Result channel (D-02 fix): the harness result is one HMAC-authenticated frame on a dedicated pipe fd with a per-run key; stdout/stderr are never parsed; a missing/duplicate/malformed/oversized/forged frame or exit without a frame (e.g. `os._exit`) is a protocol violation -> `unsafe_program`. This is a local protocol-correctness fix, not a same-address-space security guarantee (docs/architecture/V7B_RESULT_PROTOCOL.md). Tamper detection of the monitoring state is a post-run check; programs writing via `os.write(1)` or subprocesses still bypass stdout capture (only the captured-stdout observation channel is affected).
- Canonicalisation (D-01 fix, `harness.py`): dict/list/tuple/set/deque subclasses (OrderedDict, defaultdict, Counter, namedtuple...) are read through the builtin base type's unbound methods and tagged `["obj", type, [["<items>", ...], attrs...]]`; int/float/str/bytes subclasses keep `<value>`; instance state is read from `__dict__` and every `__slots__` descriptor in the MRO. No property/`__getattr__`/`__repr__`/`__iter__`/`__eq__` of user classes runs. Cycles are `["cycle", i]`; opaque objects (functions, iterators, C objects), depth > 3 objects, > 5000 items, > 50000 nodes or nesting > 40, and unreadable slots set `lossy` (blocks S2, never reaches a spurious SAME-at-S2). Set contents are sorted; mapping order is ignored unless `ordered_mapping`.
- Quarantine is conservative: any quarantined input blocks (never inspected for "may have hit"). `r_empty` (no changed units and nothing unmodelled: comment/whitespace/docstring-only) is recorded in the SufficiencyRecord and `verdict.json`; not otherwise stratified. No minimisation, no Merkle tree (a flat hash of run ids), no Supersession/void, no replay-recipe/event-stream storage, no seeds/budget grid, no calibration, no gates K1-K5.
- Control alternation (`k_alt`) virtualises only `random.seed` and `time.time/time_ns`; other entropy (uuid, os.urandom, env) is not virtualised.
- Branch coverage counts POP_JUMP_IF_*, FOR_ITER and SEND only, and treats all directions as statically reachable (conservative denominator).
- Timing: tests run real sandboxed subprocesses (about 14 s total); `env_sensitive` and replay-failure classes are tested with scripted runs, not real programs.

## Phase 2 fixes (D-05, D-06, D-09, lossy SAME)
**Spec amendments proposed (not applied to the frozen spec; they tighten, never loosen):**
- A-L1 (lossy/unobservable): a SAME input whose equality was established on a lossy canonical form (opaque value, size/depth/node cap) or on a degenerate observation is not evidence of no divergence. It does not count as the S1 `SAME` input and does not activate changed units. If no clean SAME input remains the verdict is `INSUFFICIENT(unobservable_outcome)` (existing code, no new code; spec s6 S1 "non-degenerate channel" is read to include "non-lossy"). A clean SAME input next to a lossy one gives S1 at most (S2 still needs `no equal_lossy`). Existing test `test_s1_not_s2_when_lossy` changed accordingly (it asserted NDO S1 for an all-lossy run).
- A-U1 (non-executable changed lines, D-05): changed lines inside bare string statements (docstrings) are `doc_only_lines`: vacuous, never a unit, never a witness; a documentation change is only a difference if a declared channel observes it (e.g. returning `__doc__`), then it is an ordinary witness. Comment/whitespace-only diffs vanish in normalisation. Any other changed non-executable line (e.g. a lone closing bracket) is `unmodelled_change` (B2) so R is not silently shrunk; `else:`/`try:`/`finally:` lines are exempt (structure only). `r_empty` = no changed unit and nothing unmodelled. Witnesses still take precedence over the blocker.
- A-B1 (binding, D-06): an input that fails to bind on BOTH versions is `NO_RUN(invalid_input)`: excluded from `X_eff`, never SAME, non-blocking by itself; with no other valid SAME input the result is `INSUFFICIENT(no_inputs)`. Asymmetric binding failure remains the `kind=api` witness. (`invalid_input` is a NO_RUN sub-reason, not a verdict reason code; the 18-code enum is unchanged.)

**Evidence package (D-09).** The log now holds what an independent recomputation needs, not hashes only: ProgramVersion `meta.src` (source text, cap 1 MiB each), one `EvidencePackage` record (config/H, harness.py digest, env, policy, inputs with args/kwargs (cap 256 KiB each), per-input rows with run ids, outcome, reason, lossy/degenerate/truncated flags, regions with doc/unmodelled lines, stop reason, tamper flag), per-run Observation (full canonical form) and Run summary/meta (status, limit, phase, msg, signature, hit lines, branch directions). The Verdict references the package. `python -m sbgv7 verify DIR` checks the hash chain and content ids, rebuilds changed regions from the stored sources, re-derives each input outcome (`runner.classify`) from the stored runs, then re-runs `decide.py` (`runner.finalize`) and requires value, level, primary/secondary, witness and the SufficiencyRecord body to equal the recorded ones; any mismatch fails loudly (exit 1). Over-cap items are recorded as omitted and verify exits 4 (never a silent pass).
- Not re-derivable offline and taken as recorded: the observations, per-run status/limit, stop reason, sandbox capability states. Nothing is re-executed.
- Evidence integrity (second-stage review): the log is a plaintext, unkeyed SHA-256 hash chain plus content-addressed ids. It detects ACCIDENTAL corruption and inconsistent edits only; it is **not tamper-evident against a deliberate writer** and is not tamper-proof: anyone who can write `DIR` can edit records, recompute every id and every chain hash, and rewrite `verdict.json` (whose `log_head` is stored in the same directory), and `verify` will pass, because it checks the verdict logic and chain consistency, not who wrote the facts. `verify` also takes the recorded observations as given (nothing is re-executed). A **trust anchor** outside the writer's reach is required for tamper evidence, and none exists yet: (1) the `log_head` hash (or verdict id) pinned out of band (a signed commit, a ticket, a paper appendix); (2) a signature over `log_head` by a key the writer cannot use after the fact (detached signature, HSM/KMS); (3) an append-only store with no rewrite permission for the producer (WORM bucket, `chattr +a`, transparency log); (4) a trusted timestamp (RFC 3161 or a public transparency log) so a re-forged log cannot be back-dated. Until then claim only "hash-chained", never "immutable", "tamper-proof" or "tamper-evident".
- The witness-immutable wording of the frozen spec (W3) is realised only as "append-only by convention"; no Supersession records exist.
- Sensitive data: the log is plaintext and contains source code, input values, return values, captured stdout (cap 32 KiB) and file digests. Treat `DIR` as confidential as the code and inputs; there is no redaction. Absolute paths are not stored (cwd normalised to `<WORKDIR>`).
- Not stored/yet missing vs spec s8: full event streams, replay recipes, supersession (the run-set root is a Merkle root since MB-12; the log itself is a flat hash chain, not a Merkle tree), records, a separate HarnessDeclaration/Environment/SandboxPolicy record kinds (their content is in the package).

## Child environment and determinism (second-stage review of MB-07)
**What the child is.** Every evaluated run is `sandbox-exec? python -s -P -B _child.py CFG` with `cwd` = a private temp dir and the environment from `isolation.child_env()`: an allowlist built from scratch (`PATH=/usr/bin:/bin`, `HOME`=`TMPDIR`=workdir, `PYTHONDONTWRITEBYTECODE`, `PYTHONHASHSEED=0`, `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8:strict`, `PYTHONNOUSERSITE=1`, `PYTHONSAFEPATH=1`, `TZ=UTC`, `LC_ALL=C.UTF-8`, `OMP/MKL_NUM_THREADS=1`). `os.environ` of the parent is never read, so no inherited `PYTHON*`, `LD_*`, `DYLD_*`, `LANG`, `TZ` can reach the child (tests: `test_second_stage.py`, hostile parent environment). macOS itself adds `__CF_USER_TEXT_ENCODING`, CPython may add `LC_CTYPE`.
**Why not `-I`.** `-I` (= `-E -s -P`) makes the interpreter ignore every `PYTHON*` variable, including `PYTHONHASHSEED`, which is read once at start-up and cannot be set from inside; with `-I` string hashing is random per run (probe: `-I` gives a different `hash('a')` on every start even with `PYTHONHASHSEED=0` in the environment; `-s -P -B` gives a constant). So `-I` and SD-09 (pinned hash seed) are incompatible. What `-I` additionally gave: ignoring inherited `PYTHON*` variables (now achieved by the allowlist, which is the only source of such variables), `sys.flags.isolated=1`/`ignore_environment=1` (a program can observe these flags; they now read 0, which is irrelevant to any compared channel). `-s` (no user site, so no `usercustomize`), `-P` (no cwd/script directory on `sys.path[0]`) are kept. `sitecustomize` is still imported from the interpreter's own site-packages if one exists there (none in this venv); it is not user-controlled.
**Limits.** The harness runs in the same process as the program and inserts the PROGRAM's directory at `sys.path[0]` after all trusted imports (sibling imports must work); trusted modules are therefore safe only because they are imported earlier (test shadows every stdlib module name in the program directory). A program can still import-hijack its own later imports, which is its right. This is LOCAL environment control. It is NOT validated operating-system isolation: sandbox-exec is deprecated, Linux/Docker confinement does not exist, and a program that cares can read `/proc`-like host state, the filesystem outside the sandbox reads, and the host clock.

| Source | Primary/replay runs | Alt (`ctl`) runs | Mechanism / limit |
|---|---|---|---|
| `time.time`, `time_ns` | real | shifted +1000 s x ctl | monkeypatch in harness; C code and `time.clock_gettime`, `time.localtime()` defaults read the real clock |
| `time.monotonic`, `perf_counter` | real | shifted +1000 s x ctl | monkeypatch; `_ns` variants, `process_time`, `thread_time`, `clock_gettime` are NOT shifted |
| `datetime.now/utcnow/today`, `date.today` | real | real (NOT virtualised) | C implementation reads the system clock directly; replacing `datetime.datetime` by a subclass would change type identity in canonical forms and `isinstance` behaviour, so it is a documented limit (SD-09). A program whose difference is carried only by `datetime.now` is not shifted by alt runs, so it can be reported as a confirmed witness although it is clock-dependent (a false `DIVERGENT_OBSERVABLE` risk, not a false SAME); if the value itself changes between the primary and repeat runs it is quarantined as `nondeterministic` |
| `random` module (global) | unseeded (real entropy) | `random.seed(ctl)` | `random.Random(...)` instances created by the program with their own seed are deterministic anyway |
| `os.urandom`, `uuid.uuid4` | real | seeded stream (ctl) | monkeypatch of `os.urandom`; code that bound `urandom` earlier (`from os import urandom` in a module imported before the patch) keeps the real one |
| `secrets`, `random.SystemRandom` | real | seeded (`random._urandom` rebound; second-stage addition, same entropy source as SD-09's `os.urandom`) | `getrandom`/`/dev/urandom` opened directly, `ssl.RAND_bytes`, `hashlib`-salted structures are not virtualised |
| string/bytes hash seed | `PYTHONHASHSEED=0` | `PYTHONHASHSEED=0` (not varied) | env only, fixed at start; set/dict-of-str iteration order is therefore identical across runs, including alt runs: a hash-order-dependent difference is never detected as env-sensitive |
| `id()`/addresses | OS/allocator dependent | same | not controlled; `0x...` (4+ hex digits) is normalised to `0xADDR` in messages/stdout; `id(x)` returned as an int is NOT normalised |
| `os.environ` | allowlist above | same | env only |
| cwd | private temp dir | same | `<WORKDIR>` normalised; the path differs per run |
| pid, `os.getppid` | real | real | not controlled (a program returning `os.getpid()` is quarantined as nondeterministic) |
| threads | `OMP/MKL_NUM_THREADS=1`; Python threads unrestricted | same | scheduling is not controlled |
| locale/encoding/TZ | `C.UTF-8`, UTF-8 mode, `TZ=UTC` | same | env only; `time.tzset` by the program is the program's choice |
| filesystem state | fresh private dir per run; reads outside are allowed by the sandbox profile | same | files created are digested into `side:file`; pre-existing host files can differ between runs |
| network | denied by sandbox-exec (macOS only) | same | not validated as a boundary |

Scientific effect on K2 (determinism rate): before MB-07 the child ran with `-I`, hence a RANDOM hash seed regardless of the experiment script's own `PYTHONHASHSEED=0` (`experiments/v7b/k1_spike.py` sets it in the PARENT env only, which was never forwarded). Programs whose result depends on set/dict-of-str order were classified `nondeterministic` before and are now deterministic; the determinism rate can only go up. The rate, activation rate and the K1/K2 numbers that used `sbgv7` before this change are therefore NOT comparable and must be re-measured in Phase 3 (not run here): `results/raw/k1_spike*`, `results/raw/k1_spike_postfix*`, `research/evaluation/K1_K2_FEASIBILITY_REPORT.md`, `EXPLORATORY_RESULTS.md`, `POSTFIX_RERUN_NOTE.md`, `experiments/v7b/k1_spike.py` outputs. Together with MB-01 (hex ints), MB-02 (fd-1 folded into stdout), MB-09 (pair id) and MB-12 they also change evidence ids, so old logs are not re-verifiable. V5/V6 results are unaffected (this code is not used by them).

## Ratified limitations (Decisions A and B) and non-claims
- Hash seed fixed (Decision A): hash-order sensitivity is untested and not detected. Datetime not virtualised (Decision B): false witnesses are possible for wall-clock-dependent programs.
- Not claimed: operating-system isolation (local result-channel protocol correctness and environment control only; Linux validation is Phase 3), tamper-proof logs (the plaintext hash chain is forgeable by anyone who can recompute it; a pinned `log_head` or signature held outside the log is required), or complete deterministic execution (see the Determinism table).
- Phase 2 local experiment to assess: the K2 determinism re-measurement caused by the corrected hash-seed handling (new result directories only).
