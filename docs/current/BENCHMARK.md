# Benchmark

`benchmark/benchmark_manifest.json` is the authoritative count for every
program and every pair. `benchmark/scripts/build_manifest.py` generates it from
the files; nothing else should be typed by hand.

## Corpus

64 program files in `benchmark/corpus/base_programs/`, across 12 categories
(sorting, graphs, data structures, parsing, string algorithms, FSMs, resource
management, error handling, file processing, concurrency, math, API mocks).

60 are assigned to splits by `benchmark/splits/split_assignment.json`
(stratified by category, seed 42). Four are not — `err_assert_guard`,
`math_fibonacci`, `sort_insertion_sort`, `str_palindrome` — and take part in no
experiment. They are named in the manifest so the difference between "64 files"
and "60 programs" is visible rather than a discrepancy a reader has to chase.

| Split | Programs |
|---|---:|
| train | 28 |
| dev | 10 |
| val | 9 |
| test | 13 |

All six pairwise intersections are empty, checked by
`tests/test_integrity.py::TestSplitIsolation`, which also verifies that no
variant *file* appears under two splits and that every pair's base program
belongs to its own split.

## Pairs

Each program is transformed by 12 semantics-preserving operators (SP-1…SP-12)
and 14 semantics-changing operators (SC-1…SC-14), at three seeds each. A pair
is (base program, variant), labelled EQUIVALENT for SP and CHANGED for SC.

## Two benchmark versions

### `benchmark/datasets/` — the published benchmark, 3,577 pairs

Kept unchanged so the published result stays reproducible. It has three defects,
all measured by `benchmark/scripts/observability_audit.py`, which is static and
never consults a method's score.

| | train | dev | val | test |
|---|---:|---:|---:|---:|
| nominal pairs | 1691 | 615 | 527 | 744 |
| uncompilable variants | 50 | 16 | 17 | 20 |
| no entry function | 0 | 62 | 0 | 56 |
| CHANGED but unobservable | 387 | 141 | 122 | 135 |
| statically valid | 1254 | 396 | 388 | 533 |

**Uncompilable variants (103 in total).** SP-3 inserts unreachable code and its
template list offered `if False: return None` at every insertion point,
including module and class scope, where `return` is a syntax error. `validate()`
did not catch it because `ast.parse` *accepts* a module-level `return` — only
the compiler rejects it.

The same bug left one more corrupt file outside this dataset:
`benchmark/regression/controls/ctrl_reg_018_SP3.py`, a V2-era control that no
current experiment reads. It is left in place as part of the archived record;
`tests/test_integrity.py::TestSourceCompiles` names it explicitly so it cannot
be mistaken for a source file that fails to compile.

**CHANGED but unobservable (785 in total, 135 in test).** Mutation sites were
collected with `ast.walk`, which is breadth-first, so module-level statements
are visited before anything nested and site 0 lands on scaffolding: the module
docstring, the `if __name__ == '__main__'` guard, or a `test_*` driver. The
result is a pair labelled CHANGED whose two programs behave identically when
the entry function runs. 40% of the test split's positive class.

A visible symptom: 180 variants have `if __name__ == '__main__'` mutated to
`!=`, which makes the file execute its own test driver on import. 22 of those
crash while loading, which is part of why 101 test pairs never reached the
evaluation.

**Trivially equivalent negatives.** 160 of the test split's EQUIVALENT pairs are
AST-identical to their base after normalisation — SP-10 (format normalise) is a
no-op by construction once formatting is normalised away. They are legitimate
negatives, but they are free for every method.

The two effects compound: a large block of both classes has distance exactly 0,
so the score distribution carries a tie mass containing both labels, and every
method's AUROC is dragged toward 0.5. The measured gap is large — on the test
split, SBG V5 scores 0.546 over all evaluable pairs and 0.640 over the
statically valid ones.

### `benchmark/datasets/v6/` — the corrected benchmark, 2,340 pairs

Generated by `benchmark/scripts/generate_benchmark_v6.py` from the *same*
programs, the *same* split assignment and the *same* seeds, so program-level
disjointness is preserved exactly. The operators are fixed and three
post-conditions are enforced that the original generator did not have:

| Post-condition | Effect |
|---|---|
| compiles | `compile()`, not `ast.parse()` |
| differs | the variant's normalised AST must differ from the base's |
| observable (SC only) | the mutation must reach code the entry function can execute |

The `observable` check is applied to CHANGED pairs only, and the asymmetry is
deliberate: a semantics-preserving transformation leaves the EQUIVALENT label
true wherever it lands, whereas a mutation in scaffolding leaves the CHANGED
label false.

| | train | dev | val | test |
|---|---:|---:|---:|---:|
| pairs | 1129 | 372 | 351 | 488 |
| EQUIVALENT | 559 | 213 | 182 | 242 |
| CHANGED | 570 | 159 | 169 | 246 |
| uncompilable | 0 | 0 | 0 | 0 |
| CHANGED unobservable | 0 | 0 | 0 | 0 |

Every rejected candidate is listed with its reason in
`benchmark/datasets/v6/generation_report.json`.

This is a **new test set**. It is reported separately and never substituted for
the published one. The fixes that produced it are defined by properties of the
source code — does it compile, does it differ, is it reachable — and were
specified before any result on it was computed.
