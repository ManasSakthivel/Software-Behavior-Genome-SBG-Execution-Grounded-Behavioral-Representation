# Figures

Generated by `experiments/final/make_figures.py` from the authoritative
artifacts under `artifacts/final/`. Run `make figures` to regenerate. No number
in any figure is typed by hand.

They are SVG, written directly rather than through a plotting library, for two
reasons: a reproducer needs no dependency beyond the standard library, and a
text format stays diffable — a changed number is visible in `git diff` instead
of hidden inside a binary.

## Captions

**Figure 1 — Main benchmark AUROC.** Point estimates with 95% confidence
intervals from a cluster bootstrap that resamples base programs, because pairs
inside one program are not independent. Three arms: the published protocol
(which traces self-test drivers, so its exception features carry a leaked output
oracle), the same benchmark under the output-free protocol, and the corrected
benchmark under the output-free protocol. The dashed line marks 0.5; the dotted
line marks the 95th percentile of AUROC under within-cluster label shuffling.
The structural baselines sit far below 0.5 in every arm — structural similarity
is anti-correlated with semantic equivalence on this benchmark, which is the
inversion execution is meant to resolve.

**Figure 2 — Where the test split's pairs go.** The published AUROC was reported
against 744 pairs and computed on the 643 that executed. All 101 differences are
categorised, and the 123 further pairs excluded by the static validity audit are
shown separately. Nothing is dropped without a name.

**Figure 3 — SBG against an output-reading reference.** The reference compares
program outputs, which makes it a ceiling rather than a competitor. Earlier
releases reported its scores — 12/12 and 14/15 — under headings that read as SBG
results. The threshold τ\* = 0.08 was fixed before these pairs were scored.

**Figure 4 — What the published protocol traces.** Static analysis of all 64
corpus programs; nothing is executed. Entry-point discovery returns the
call-graph root, which in this corpus is the program's own `test_*` self-test
driver, so its `assert` statements execute inside the traced region and the
exception features record whether the program's own unit tests passed.
