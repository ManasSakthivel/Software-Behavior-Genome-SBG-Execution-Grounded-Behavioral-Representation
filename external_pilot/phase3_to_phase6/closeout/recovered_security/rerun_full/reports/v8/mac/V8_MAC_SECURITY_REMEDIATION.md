# V8 macOS security remediation: A08 and P04 (2026-11-18)

Scope: macOS (Darwin), Python 3.13, `sandbox-exec`. Nothing here is a security guarantee. Linux isolation is unverified. `sbgv7/` is untouched; every fix is in `sbgv8/`.

## 1. Reproduction and code-path traces (before any change)
Pre-fix suite output: `results/v8_mac_security/attack_suite_before.json` (16 rows: control + original 15). A08 and P04 both reported `SUCCEEDS (open)`.

### A08: stdout divergence hidden by patching `Cap.write`
Attack source: variant does `m = sys.modules['__main__']; m.Cap.write = lambda self, s: len(s)` at import, then `print('extra output'); return x+1`. Base returns `x+1` silently, so the honest verdict is DIVERGENT_OBSERVABLE (stdout differs).
1. `runner.Ctx.run` -> `isolation.run_script(HARNESS, ..., channel=True)` -> `_child.py` -> `runpy.run_path(harness.py, run_name="__main__")`: harness and program share one process.
2. `harness.main()` wraps import and call in `contextlib.redirect_stdout(cap)` with `cap = Cap()` (an `io.StringIO` subclass). `print` therefore writes to `sys.stdout is cap`; **the bytes never reach fd 1**.
3. The attacker replaced `Cap.write` (class attribute, reachable through `sys.modules['__main__']`), so nothing is stored. `finish()` reports `res["stdout"] = ""`, `stdout_trunc = False` in the HMAC frame (the frame is authentic: the attacker did not forge it, it lied by omission).
4. The parent's only other source, `Result.stdout` (real fd 1), is empty too, so `runner.Ctx.run` folds nothing into `fd1`. Base and variant observations are equal -> SAME -> NO_DIVERGENCE_OBSERVED. `verify` recomputes from the same stored observations; the shadow runner compares return values only. No check can fire.
Root cause: the only record of program stdout is produced by code the program can modify; the parent has no independent copy.

### P04: edit an unverified field and re-chain, re-binding the sidecar
`trust.forgery_suite` P04: set `Run.meta.cpu_s/wall_s = 0`, `_rewrite` the log (full re-chain), fix `verdict.json.log_head`, then set the sidecar's `log_head` and `evidence_sha256` to the new values.
1. `sbgv7.verify` recomputes outcomes/verdict from stored runs; it never reads `Run.meta` timings or `summary.status/detail`, so the edit is invisible to it (documented limit in verify.py).
2. `trust.check_sidecar` binds the sidecar to the log by `sha256(evidence.jsonl)` and the head: both are public, recomputable values with no secret, so the attacker recomputes them. The sidecar parts still equal the Run records.
3. `verdict.json` agrees with the new head. Chain, verify, sidecar, verdict.json all pass. Root cause: every binding was recomputable by whoever can write the directory; there was no secret and no value held outside it. The same trick applies to any decision-relevant field verify does not recompute (run status/detail, timings, limits).

## 2. Fix A (independent capture), `sbgv8/_tee_child.py`, `sbgv8/procsep.py`
- `collect.run_capture` now runs the unchanged engine inside `procsep.Supervisor`, which swaps the module attribute `isolation.run_script` in the **parent process only** (restored in `finally`; Ctx.run looks it up at call time). No sbgv7 file changes; the harness digest recorded in the package is still the real `harness.py`.
- For every harness spawn the supervisor substitutes the child entry `sbgv8/_tee_child.py` (same `_child.py` bootstrap, same sandbox, rlimits, channel fd; the harness is run unmodified via `runpy`). The wrapper replaces `contextlib.redirect_stdout` so that `sys.stdout` becomes `Tee(cap)`: every `write` is first emitted on the real fd 2 as `@@SBGV8T@@<run nonce> <seq> <O|W|X|C> <hex>@@`, **then** handed to `Cap`. Patching `Cap.write` therefore cannot suppress the record. `os._exit` is wrapped to emit the closing record (`C`, true char total) so the parent can tell a complete stream from a suppressed one.
- The parent (`parse_tee`, `judge`) reads the child's real fd 2 (and fd 1) from its own pipes, strips tee records (genuine stderr is preserved), and compares the reconstructed program stdout (after the harness's own truncation rule and the same normaliser `runner.norm_parent`) with the harness-claimed `stdout`/`stdout_trunc`. Verdicts per run: `match`, `no_frame` (no authentic result; the V7-B engine already fails safe), `mismatch`, `incomplete` (no open/close record, sequence gap, foreign or malformed record, stderr cap hit, total != closing record).
- Per-run records (`v8_capture.json`, schema `v8.capture.1`) state explicitly: fd1/fd2 length+sha256+truncated, tee counters (overflow, gaps, foreign, malformed), harness claims, termination (`status/detail/signal/returncode`), `flooded`, `orphans_found/cleanup_verified`, the verdict and reasons. Nothing is truncated silently: tee overflow beyond 262144 chars is recorded (`X`) and the true total travels in `C`.
- **A child-side claim of completeness is never sufficient**: the parent requires its own record to exist and agree. Any mismatch, missing record or incomplete collection => `capture.trusted = false`.
- Fail-safe to the decision layer: `run_capture` returns `verdict = INSUFFICIENT` (engine value kept as `v7b_verdict`, reasons in `v8_untrusted`); `adapter.load_record` sets `integrity_ok = False` and `meta.untrusted/effective_verdict`, which `calibrate.decide` and the profile already map to INSUFFICIENT; `procsep.decide` is the pure rule.
- Side effect: none on the V7-B verdict or evidence log (the tee uses stderr, not fd 1, so no new `fd1` observation appears).

## 3. Fix B (schema + anchor), `sbgv8/evidence_schema.py`
- Exact typed schemas (missing/extra keys, bool-vs-int, hex lengths, sizes) with explicit versions `v8.parts.1`, `v8.capture.1`, `v8.anchor.1`; unknown versions are rejected. `check_sidecar` now enforces the sidecar schema first (also catches duplicate input ids, wrong types).
- Cross-binding capture <-> log: capture `log_head` and `evidence_sha256` equal this log's; `config_sha256` equals the package config; `harness_sha256` equals the package; run `seq` contiguous (reorder/duplicate/partial), nonces unique, exactly as many capture records as Run records, and per run: `status/detail/protocol_error`, `input_hash`, `side`, `mode`/`run_kind`, `cpu_s/wall_s`, and the observation's `stdout` digest equal the log. So run status/detail/timings, which `verify` ignores, are now cross-checked.
- Anchor (`v8_anchor.json`): HMAC-SHA256 over the digests of `evidence.jsonl`, `verdict.json`, `v8_parts.json`, `v8_capture.json` plus session id and key id. The key comes from `anchor_key=` or `$SBGV8_ANCHOR_KEY` in the controller process, is never in the evidence directory and never passed to the child (child env is an allowlist; tested: the key and any `SBGV8*` variable are absent from the child's environment).
- **What the anchor proves**: the MAC producer knew the key and none of the four files changed afterwards. **What it does not**: honest observation; resistance to a writer who holds or can read the key (the evaluated program runs as the same user with default-allow reads, so a key *file* in a readable place is no secret from it; deploy the key out of the evaluated user's reach); that this is the run the reviewer expected. A key-holding writer who recomputes everything is undetectable in-directory: only `pinned_head` supplied out of band detects it (tests: `test_anchor_boundary_writer_with_key_is_undetected_without_pinned_head`). Without a supplied key the anchor is reported `unverified_no_key`, never `ok`; P04 is "detected" only where the verifier holds the key and the attacker did not. Without any key the capture binding alone still catches the old P04 form (it also needs the capture file re-bound), but a writer who re-binds every file passes (tested; no claim).

## 5. Known limits (unchanged by this work)
Same address space (M-4): a program that replaces `sys.stdout`, `contextlib.redirect_stdout` or the tee emit function, or learns the per-run nonce (it is in argv) and forges matching records, defeats the capture (pinned by `test_known_limit_program_that_swallows_its_own_sys_stdout_is_not_visible`). Binary stdout is recorded in the decoded form `isolation.py` keeps (invalid bytes become U+FFFD); incomplete pipe reads are inferred from missing close records / stderr cap / orphan flags, not observed. `Supervisor` is not thread-safe. Linux is unverified.
