# V7-B baselines: implementation and fairness (DEVELOPMENT / EXPLORATORY)

Date 2026-11-17, branch research/v7b-final-validation. Code: `sbgv7/baselines/{baselines,run}.py`; tests: `tests/v7/test_baselines.py` (9 passing, real sandboxed runs). Raw: `results/raw/baselines/<arm>/<pair>/<B*>/` (evidence.jsonl per baseline per pair); processed: `results/processed/baselines_per_pair{,_final}.jsonl`, `baselines_summary.json`. Driver: `python -m sbgv7.baselines.run run|summarize`. V5/V6 code and committed artifacts were only read; nothing was retrained.

**Data and tuning statement.** All 321 pairs are the K1-spike development pairs (QuixBugs buggy/fixed 31, QuixBugs SP negatives 85, v8/v10 synthetic 150, BugsInPy single-file units 46 driven of 55), all non-pristine. Pair manifest = the K1 spike's own task builders (`experiments/v7b/k1_spike.py`); inputs = the exact `inputs.json` V7-B received (read from `results/raw/k1_spike/<arm>/run1/`). Nothing was tuned on anything but these development rows. The only fitted quantities are B4's threshold (tuned on the development half with even project-name hash parity; the other half was not scored separately) and B5's decision threshold (tuned on V6 train out-of-fold scores only, never on holdout). No sealed/holdout split was touched. These results are descriptive, not a performance claim; labels are as given (synthetic EQUIVALENT is "equivalent under looser equality", see K1 report finding 3).

## Common conditions (identical for B1, B1+rep, B2, B3)
- Same pair list, same inputs, same runner: `sbgv7.runner.Ctx.run` -> `sbgv7.isolation.run_script` (fresh sandbox-exec child per run, same rlimits, per-run cpu 2 s / wall 5 s as the K1 spike) and the same V7 boundary comparator (`sbgv7.compare.compare`, same C_obs, normaliser, strict type tags).
- Budget: 60 CPU-s per pair (V7-B headline), unit = child CPU (isolation `cpu_s`) plus the calling thread's parent CPU (our overhead), checked before each input. V7-B itself stopped at its first witness and spent 455 CPU-s child-only over the 321 pairs; budgets used by baselines (child+parent): B1 about 151 s, B1+rep about 543 s, B3 about 1407 s total (cap not reached except a few B3 pairs, max 63 s). V7-B's own parent overhead was not measured in the K1 spike, so V7's reported CPU is a lower bound.
- OMP_NUM_THREADS=1, 4 worker threads, no stray processes left. Early stop at first reported divergence (this only saves CPU).
- Output vocabulary is DIVERGE / NO_DIFF (not V7's); baselines do not abstain. A one-sided limit, missing entry, or import error on one side counts as a difference; both sides failing identically counts as no difference.

## Per baseline

**B1 same-input differential execution.** Measures: any observable difference on the shared inputs. One run per side per input, no repeats, no replay, no sufficiency/activation check. Config: nothing beyond the above. Fairness: same inputs, same runner and comparator, so differences from V7-B come only from V7's replay/determinism/sufficiency logic. Differences from V7-B: no confirmation, so flaky or environment-sensitive outputs become DIVERGE; unactivated changes become NO_DIFF instead of INSUFFICIENT. Status: **Implemented and verified** (unit tests; 321 pairs run, 0 errors). Result: DIVERGE 29/31 QuixBugs buggy-fixed, 7/46 BugsInPy units, 71/150 synthetic (54/78 CHANGED, 17/72 EQUIVALENT), 32/85 SP negatives. B1 reports DIVERGE on 55 pairs where V7-B did not (mostly 31 SP-2 renamed-entry negatives and 18 synthetic renamed entries, where V7 returns `unsupported_signature`, plus two one-sided-limit infinite loops); V7-B witnesses were never missed by B1 (0 pairs V7 DIVERGENT, B1 not) on these inputs.

**B1+rep.** Measures: B1 plus V7-B's repeat counts: `r_det=3` runs per side per input, and `r_replay=5` fresh replays per side on a differing input; DIVERGE iff both sides self-consistent and every replay reproduces. No sufficiency/activation gate and no `k_alt` control-alternation runs (these are V7's sufficiency/environment machinery, deliberately excluded). Fairness: same repeat counts and budget unit as V7-B, so repeated-run overhead is charged. Status: **Implemented and verified**. Result: identical to B1 on all but 2 pairs (B1 DIVERGE, B1+rep not: irreproducible); about 3.6x B1's CPU.

**B2 test replay / regression style.** Measures: pass/fail of each declared test on each version; DIVERGE iff some test's pass/fail differs between versions (fix or regression). A test = a declared input with a declared expected output; pass = returned value equals expected (tuple==list). Applicable only to QuixBugs arms (json_testcases expected outputs; same inputs as V7-B, first 12). Fairness: same inputs/runner/budget; the oracle is extra information V7-B did not use (favours B2). Not run (reason recorded per row) on synthetic and BugsInPy units: no declared expected outputs, no project test suites (cannot run third-party suites without Linux isolation). Differences: compares to an expected value rather than version-to-version, so it can also report a pass-to-pass-equal pair as no diff where both fail equally. Status: **Implemented and verified for QuixBugs (116 pairs); NOT RUN for synthetic (150) and BugsInPy units (46)**. Result: 29/31 buggy-fixed DIVERGE, 29/85 SP negatives DIVERGE.

**B3 coverage-guided random differential (minimal; NOT AFL).** Measures: B1's rule on the shared inputs first, then mutated inputs. Corpus seeds = the shared inputs; mutate one argument (JSON types: int/float/str/list/dict/bool/None; 1-3 stacked mutations), run both versions once, keep a mutant iff it hits a (side, line) not seen before (line coverage from the V7 harness, union of both versions). Seed 1001 (first spec `exploration_seed`), fully deterministic (tested). Cap 60 CPU-s (child+parent) plus `max_execs=60` mutants per pair, a wall-clock deviation (CPU alone would allow about 1000 mutants; per-run cost is mostly interpreter/sandbox start, about 0.1 s wall). Honest limits: no instrumented forkserver, no havoc/splice/dictionary stages, no edge-hit-count buckets, no power schedule, JSON-representable inputs only (same as the engine), argument-level mutation only; this is a small mutation loop, not a stand-in for AFL/libFuzzer/Hypothesis-style tools. Decision rule single-run like B1 (no confirmation). Status: **Implemented and verified (minimally)**. Result: 5 pairs found only by mutation (all synthetic/SP, within 5-19 mutants); otherwise equals B1 (synthetic 75/150 DIVERGE, BugsInPy 7/46).

**B4 edit-size heuristic.** Measures: changed lines (`sbgv6.features.changed_lines`, count in both versions) >= t. No execution. Threshold t chosen on the development half only (balanced accuracy, ties to smallest t): result t=97, tune balanced accuracy 0.50, i.e. no usable signal on this data (it predicts NO_DIFF for all but 2 pairs). Fairness: budget ~0 (static); same pair list. Its labels-fitted threshold is the only label use among B1-B4. Status: **Implemented and verified (tests: edit_size, tuning rule); non-informative on these pairs**.

**B5 V6 C0g score.** Measures: V6 `C0g_V6B_gated` LR score from frozen artifacts (`artifacts/v6/final/predictions_final.csv` train OOF, `artifacts/v6/holdout/results/predictions_{v10,v8test,quixbugs_declared}.csv`), joined by pair id; V6's own gate status other than ACTIVATED maps to ABSTAIN_V6; threshold 0.472 from train-OOF ACTIVATED rows (balanced accuracy 0.741 there). This is a **lookup of V6's earlier scoring, not a re-execution**: V6 used its own inputs/pipeline and its CPU cost is not measured or matched, and the V6 holdout rows were scored once earlier (V6 has seen these benchmarks; not pristine). Coverage: QuixBugs 116/116 (buggy 10 DIVERGE, 11 NO_DIFF, 10 abstain), synthetic 121/150 joined (29 pair ids absent), BugsInPy units NOT RUN (V6's BugsInPy rows are different function-level extractions; no join). Fairness caveat above means B5 is not budget- or input-matched. Status: **Implemented incompletely (artifact lookup; 237/321 pairs scored; 29 synthetic + 46 BugsInPy NOT RUN with reasons in the per-pair file)**.

## Not implemented, therefore NOT compared
No published tool was run. Specifically not implemented or evaluated: **Shadow symbolic execution** (Palikareva 2016), **DiffKemp** (static, LLVM IR/C kernels, not applicable to Python), **Mokav**, **Testora**, **DiffTestGen**, **Cleverest** and any other LLM differential-testing/test-generation tool, **AFL/libFuzzer/Atheris** and property-based generators (B3 is only a minimal analogue), Evans & Savoia differential unit testing, dynamic impact analysis (Law/Orso), Chianti, Daikon-style invariant diffing, regression-verification provers, flaky-test tools (iDFlakies, DeFlaker), and LLM equivalence judges (EquiBench-style). Any claim of superiority over these is unsupported by this work.

## Known gaps
No pristine/holdout evaluation; no Linux-container isolation (macOS records are `policy_below_minimum`); B2 and B5 cover only part of the pairs; matched-coverage FAR comparison for gate K4 is not computed here (only raw counts); synthetic labels are not adjudicated; B4's tuned threshold shows no signal, so it should not be read as "edit size is useless" beyond these development pairs.
