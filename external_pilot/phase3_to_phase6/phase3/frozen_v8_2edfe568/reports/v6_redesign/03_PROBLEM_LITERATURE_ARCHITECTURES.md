# 03 — Problem Definition, Literature Review, Architecture Alternatives (Phase 1)

## 1. What SBG should measure

Seven nearby problems, and where SBG stands:

| Problem | Ground truth | Can SBG address it? | Decision |
|---|---|---|---|
| 1. **Behavioural change detection** between two versions under a test-input distribution | Observable divergence of executions | Yes — this is a pair question | **Primary problem** |
| 2. Semantic program equivalence | ∀ inputs equal | Undecidable in general; dynamic evidence can only *refute* equivalence | Out of scope as a claim; used as label semantics only |
| 3. Defect-inducing change detection | Change introduced a fault | Needs a specification/oracle; behaviour change ≠ defect | Out of scope |
| 4. Regression detection | Previously-passing test now fails | Needs oracle; equivalent to output comparison | Baseline only |
| 5. Test adequacy | Tests expose the change | SBG's evidence layer *measures* it (is the changed region activated?) | Component, not goal |
| 6. Behavioural representation learning | Embedding quality | Learned representations need large training corpora absent here | Not pursued |
| 7. Change impact assessment | Which tests/outputs are affected | Chianti-style (Ren et al. 2004) is static+dynamic; overlaps with evidence layer | Related work |

**Defensible research problem (V6).** *Given two versions (P, P′) of a function and a fixed input set, decide from the executions whether P′ is observationally different from P — as a continuous distance with explicit evidence about whether the executions were informative.*

Critical observation that shapes everything: if outputs are available, **differential testing** (run both on the same inputs, compare return value/exception) is the natural, cheap and strong detector (McKeeman-style; the oracle problem is what metamorphic testing addresses, Chen et al. 2018). SBG therefore has two honest regimes:

* **R1 — oracle-free**: no return values, no stdout and no exception *messages*. Only internal execution observations. This is the regime V5 declared ("output-free"). SBG can only add value if internal behaviour carries information beyond what changes in output would show — and only when outputs cannot be compared.
* **R2 — oracle-available**: return values/exception types included. The differential-testing baseline is mandatory and is expected to be very strong; SBG adds value only if it is *complementary* (e.g. detecting a change when outputs agree on the sampled inputs, or when the input set under-covers the change).

A third, labelled **"latent change"** question — are internal executions different when outputs agree? — is not answerable with the available benchmarks because no benchmark labels it. V6 will *report* it descriptively and claim nothing.

## 3. Architecture families

All four+one are built as **feature blocks over the same traces** (the traces from `SandboxRunner`), so comparison is an ablation of identical executions, not four systems.

| Family | Representation | Distance | Expected strength | Expected weakness |
|---|---|---|---|---|
| **A. Invariant-centred** | Per-point (entry / exit / loop-head), per-slot (first-appearance order) predicates: type, sign, zero, emptiness, length bucket, constant; slot-pair relations (<, ≤, =, ≠, len=); support counts | Confidence-weighted symmetric difference of the invariant sets | Rename/reformat invariant; Daikon-grounded; stable across inputs | Needs enough observations; loses ordering; point alignment across versions is approximate |
| **B. Sequence/transition** | Distribution over abstract transitions (statement-kind → statement-kind, branch outcome, back-edge) per input | Jensen–Shannon divergence | Captures control-flow change; line-number-free | Dead-code/refactoring shifts mass (edit-size confound risk) |
| **C. Graph** | Dynamic CFG over AST-statement ids with edge frequencies | Weighted graph difference (edge-frequency L1 / JSD) | Richest structural view | Node alignment across versions; heavier; risk of just re-encoding the diff |
| **D. Evidence-aware hybrid** | Blocks A+B(+R, return-state in R2) **plus** an evidence vector: per-side completion, truncation, timeout, exception, coverage; and activation status of the changed region | Block distances + evidence → status ∈ {ACTIVATED, NOT_ACTIVATED, UNKNOWN}; reliability-weighted fusion | Never conflates "no data" with "no change"; calibration per status | More components → more ways to overfit; fusion must be trained honestly |
| **E. (added) Change-activation-gated differential** | Align executed lines to the *diff* between P and P′ (difflib on normalised AST dump / source lines); features: fraction of executions touching changed lines, events within the changed region, first-divergence position in the per-input event sequence | Gated divergence: distance restricted to post-first-divergence events | Directly answers "did the executions even reach the change" (Chianti/slicing idea, dynamic and cheap); counters edit-size by looking at *where* behaviour diverges rather than how much text changed | Needs source-level diff; weak for large rewrites |

**Selection rule (declared before experiments).** The architecture is chosen on **development data only** (v8 train+val, program-grouped CV) by: (i) highest mean grouped-CV AUROC in the oracle-free regime for the *raw (unsupervised)* distance and for a fixed-capacity LR on the block features, (ii) subject to non-inferiority on the edit-size-stratified and leave-one-transformation-family-out analyses, (iii) ties broken in favour of the simpler/more interpretable architecture. D is **not** presumed: if the evidence layer adds nothing in ablation it is reported as an output of the system (reliability reporting) rather than as a predictive component. Final choice is recorded in `SBG_V6_FINAL_ARCHITECTURE.md`.
