## Spec expectation changes (conscious, no test weakened)
- Integer canonical form is `["int", "0x.."]` (hex) instead of decimal: `test_phase2_fixes.py::test_verify_divergent_forged_to_same` forged values changed from `"6"`/`"-5"` to `"0x6"`/`"-0x5"`; `baselines.plain` parses with base 0. Reason: `str(int)` raises past 4300 digits (MB-01). All evidence ids for programs returning ints change.
- `test_core.py` module skip reason now includes the sandbox probe detail (MB-16 item 12); no assertion changed.
- Pair ids, policy ids and `run_set_root` values differ from pre-change evidence (MB-07, MB-09, MB-12); old logs are not re-verifiable by this code for pair id.

## Honest gaps and risks
- MB-07 alt-run virtualisation covers `time.time/_ns`, `monotonic`, `perf_counter`, `random.seed`, `os.urandom`/uuid4; NOT `datetime.now` (documented), `secrets`/`random.SystemRandom` (they bind `os.urandom` at import), env or `time.sleep`. `test_mb07_real_env_sensitive_case` is no longer clock-boundary dependent (second stage).
- MB-07 changed the child interpreter flags from `-I` to `-s -P -B` (the env is built from scratch by `child_env()`; justification and experiment in `V7B_IMPLEMENTATION.md`). This is local environment control, not validated OS isolation. K2-style determinism rates must be re-measured (not done here, no experiments).
- MB-06: the interpreter-3.13 requirement of SD-07 is only a `policy_below_minimum` flag, not a `sandbox_failure` gate; `rlimit_as`/`rlimit_nproc` are advisory by SD-07, so every macOS run stays `policy_below_minimum=true`.
- MB-02: buffered `sys.__stdout__` writes are now flushed by the harness before it exits (second stage). Still lost: output buffered in a stream the program created itself around fd 1 (`open(1,'w')`, `os.fdopen(1)`), output after a user `os._exit` (the run is `unsafe_program` by design, SD-11), and stderr (excluded by contract). Import-time prints remain part of stdout (UD-3 import-time option A, as built).
- MB-11: a run in progress is not interrupted (granularity is the run); the mid-input stop leaves that input's runs in the log but not in `rows` (verify tolerates this).
- MB-15: older evidence without `v6_features_sha256` verifies without the digest check.
- Result-channel protocol (D-02) correctness and OS isolation are different claims: nothing here validates the macOS sandbox as a security boundary.
- Not implemented by design: CB-01..CB-04 (wait on UD-1..UD-4), anything Phase 3.

- Evidence integrity: the log is an unkeyed plaintext hash chain; a writer can forge a self-consistent log and `verdict.json`. It is not tamper-evident without an external trust anchor (pinned `log_head`, signature, append-only store, timestamp); see `V7B_IMPLEMENTATION.md`.
- `datetime.now/today`: not virtualised, deliberately (changing `datetime.datetime` would alter type identity); table of what is and is not controlled is in `V7B_IMPLEMENTATION.md`.
